01生产流程 PIPELINE 产出 draft.md

素材经过四道关卡变成定稿，每一道都有明确的放行条件

PIPELINE · 单章的生命周期
INPUT
素材入厂
条条带来源
→
起草
倒序写作，主体先行
→
审查
四角色并行打分
→
定稿
归档回灌

打回时只改被点名的条目 —— 改方向永远比推倒重来便宜。

NOTE 审查不是挑错字，是四类视角各查各的：事实、结构、深度、文风。

证据可溯

每条事实都能回指到调研台账里的来源链接。

概念先立后用

信息按依赖排序，任何概念不得先于定义被引用。

图文互证

机制章节配架构或流程图，图与正文互相印证。

循环收敛

审查最多三轮，不收敛就升级人工裁决。

review.md 示例
# Review round 1
[事实] 第2章 延迟数字缺来源 → 补 ledger#12
[深度] 第3章 只讲了用法，缺边界条件 → 补反例
[文风] 第1章 "众所周知" 删
02系统分层 ARCHITECTURE 产出 design.md

三层职责清晰，层与层之间只走统一协议

接入层
Web
浏览器端
API
第三方调用
CLI
本地终端
↓ 统一协议
控制层
调度核心
任务编排与限流
规则引擎
校验与策略
↓ 读写分离
存储层
主库
事务数据
缓存
热数据
对象存储
大文件
P0阻断发布事实错误 · 引用失效
P1本轮必改结构缺陷 · 深度不足
P2择机优化措辞与排版
threshold — 加权总分 ≥ 8.0 且无 P0 才放行

层间解耦

跨层调用一律走协议，不允许直连存储。

语义上色

橙=核心动作，黑=终点，黄=中间态，主次立现。

失败可见

降级路径画虚线，不让异常藏在图外。

一屏一事

一张图只回答一个问题，多了就拆。

design.md 示例
# 分层约定
layers: [接入层, 控制层, 存储层]
rule: 跨层调用必须走统一协议，禁止直连存储
提炼 SUMMARY WRITING PIPELINE

六道工序，三道闸门；审查不过关，就打回重来

01简报八项确认，不写模糊的题brief.md

来源是底线

没有来源的断言，一律降级为观点或删除。

闸门防跑偏
