# MCP 入门速览

把工具接给大模型的通用插头：一次封装，处处可用。

## 为什么需要 MCP (WHY)

大模型只会生成文本与代码，真正干活要靠外部工具：查库、发请求、读写文件。
每接一个工具就手写一遍胶水代码，成本高、不可复用，换一个模型还要重写。
MCP 把「工具如何被暴露与调用」标准化成协议，模型侧只认协议，不认具体实现。

### 它解决了什么

- 工具接入重复造轮子
- 上下文里塞满私有 API 文档
- 换模型就要重写集成层

> 注意：MCP 只标准化调用方式，权限与安全仍由宿主（Host）控制。

## 三个核心概念 (CORE)

Server 暴露能力，Host 负责鉴权与会话，Client 在两者之间转发调用。
可暴露的能力分三类：工具（Tools）、资源（Resources）、提示词（Prompts）；
实践上一个 Server 只做好一件事。

```yaml
# server 最小配置
name: notes-server
transport: stdio
tools:
  - search_notes
  - read_note
```

> 附注：配置文件与技能清单一样，改动即应被回归验证。

## 部署与选型 (DEPLOY)

本地工具用 stdio，延迟最低；远程服务用 HTTP/SSE，注意鉴权与超时；
工具描述写得越清楚，模型选择就越准。

| 场景 | 传输 | 要点 |
|---|---|---|
| 本地文件/脚本 | stdio | 延迟低，随进程启动 |
| 远程服务 | HTTP/SSE | 必须鉴权，设超时 |

---

总结：MCP 的价值不在协议本身，而在生态——工具写一次，所有支持协议的模型都能用。
