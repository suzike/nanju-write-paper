# 配图方案：风格化框图 / 架构图 / 流程图 / 时序图

> 原则：**不用 Mermaid 等自动排版渲染器**。所有图用主题模块（HTML/CSS）或固定坐标的内联 SVG 手搭，
> 样式继承 [style-guide.md](style-guide.md) 色板与字体，布局显式写死——从构造上杜绝自动布局的抽风。
> 样式库：[assets/theme.css](../assets/theme.css)；机器检查：[assets/diagram-check.js](../assets/diagram-check.js)。

## 1. 选型表：内容形态 → 图式

| 文案形态 | 图式 | 模块 |
|---|---|---|
| 有先后顺序的步骤/阶段 | 流程行 | `.frow` + `.fcard`/`.state` + `.arrow` |
| 分层结构（栈/层级/体系） | 分层架构图 | `.arch` + `.dnode` + `.varrow` |
| 多方协作/调用往来 | 时序图 | `.seq`（`.actor/.life/.msg`） |
| 阈值/档位/分级 | 分级条 | `.tier` |
| 多路汇聚到一个闸门/枢纽 | 汇聚图 | `.fan` |
| 循环/闭环（PDCA、回路） | 环形图（仅暗页/封面用） | `.ring` |
| 并列要素/清单 | 卡组 | `.fcard` 组或 `.points` |
| 主线流程总览（封面/总结） | 芯片链 | `.chipline` |

一篇深度文章建议 3–6 张图：每章至少 1 张主图；两张同类信息宁可拆两图不挤一图。

## 1.5 配图配额（硬约束，S4 逐条验收）

1. **真图配额**：深度长文（≥5 章）真图 **≥4 张**；图式多样性 **≥3 种**（从 流程 / 架构 / 时序 / 汇聚 / 环形 / 信息图 中选）。
2. **"真图"定义**：流程条、架构图、时序图、汇聚图、环形图、信息图（数字卡网格/时间线）、芯片链。**表格、代码卡、要点清单不计数**——它们是排版模块，不是图。
3. **fig-N 对账**：大纲配图计划里的每个 fig-N 必须在成稿中可定位且为真图；缺失或降级成表格 = P1 缺陷，S4 的 R2 负责对账。
4. **时序图触发词**：文案出现"A 调 B、B 回 C、多轮往返"类协作描述 → 首选时序图，不许退化为流程条。
5. **信息图触发词**：出现 ≥4 个并列数字/指标 → 做数字卡信息图（.statrow + .big），不许散在正文里。
6. **架构图触发词**：出现分层/组成/依赖 → 分层架构图（.arch），每层节点 ≤4。

## 2. 文字预算（防"文字出边界"的第一道闸）

节点宽度和字号因画幅而异，落笔前先算字数预算：
`可容纳汉字数 ≈ (节点宽px − 2×内边距) ÷ 字号px`（等宽英文按 0.6×字号/字符计）。

速查值（面板内 flex 均分节点）：

| 画幅 | 面板内容宽 | 3 列节点≈汉字/行(标题) | 4 列节点≈汉字/行 | 描述文字 |
|---|---|---|---|---|
| A4 794px | ~640px | 8–9 | 6 | ≤2 行，每行 ≤11 字 |
| 卡片 1080px | ~830px | 12 | 9 | ≤2 行，每行 ≤15 字 |
| 宽屏 1280px | ~1000px | 15 | 11 | ≤2 行，每行 ≤19 字 |

规则：
1. 标题超预算 → 换行（允许 wrap），但节点高度按"标题 2 行 + 描述 2 行"预留；
2. **禁止** `white-space:nowrap` 出现在节点文字上（芯片 `.chip-dark`、`.lab` 等短标签除外，且必须带字数自查）；
3. 箭头、编号等装饰字符不占语义预算，但要计入 flex 间隙（`--gap`）。

## 3. 布线纪律（防"压线 / 线条紊乱"）

1. **方向唯一**：一张图只允许一个主方向（L→R 或 T→D）。回边不画长线，用参考图 15 的做法：
   橙色虚线回弧/`↺` 符号 + 底部 `loop/verifier` 式等宽注记行，或 `.callout` 说明。
2. **线不穿节点**：连线只存在于节点之间的间隙。CSS 图里"线"就是 `.arrow`/`.varrow`（放在 flex/grid 间隙里），
   天然不穿节点；SVG 图必须让线段两端点落在节点边缘坐标上。
3. **标签必须带底色**：任何放在线旁的文字一律用带背景的芯片（`.elab`、`.msg .lab`），禁止裸文字漂在线上。
4. **正交优先**：SVG 折线只走横平竖直（H/V 段），禁止斜线与贝塞尔曲线。
5. **交叉预算 ≤1**：数一遍交叉数，>1 就重排（换节点顺序 / 拆成两张图 / 改成分层图）。
6. 时序图只画水平消息线；**不画自调用消息**（自调用改写成步骤注记）；激活条 v1 不做。

## 4. 时序图百分比公式（CSS 版）

设总列数 `N`、消息从列 `a` 到列 `b`（均从 1 起）：
- 线起点 `--x1 = (min(a,b) − 0.5) / N × 100%`
- 线宽 `--w = |a−b| / N × 100%`
- 标签位置 `--xm = ((a+b)/2 − 0.5) / N × 100%`
- b < a 时加 `msg--rtl`；虚线回程加 `msg--dash`
- 每个参与者一列，**必须**为每列放一个 `.life`（内联 `grid-column:i`），生命线自动贯穿（CSS 已定 `grid-row:2/99`，禁改回 `-1`——隐式网格下 `-1` 不指向末行）

例（N=3，a=1→b=3）：`--x1:16.67%; --w:66.66%; --xm:50%`。

## 5. SVG 兜底（CSS 表达不了的复杂分支才用）

- `viewBox` 固定（如 `0 0 960 560`），坐标取 **20px 网格**对齐；
- 线：`stroke="#cd642d"`（暗页 `#eda55f`）`stroke-width="2"`，`marker-end` 三角箭头，转角用两段正交线；
- 文字：`<text>` 逐个定位，字号 = 画幅 `--fs-small`，**先按 §2 预算字数再落坐标**；
- 禁止 `textPath`、禁止自动布局；节点矩形 `rx=10`、白底 `#fbfaf5` 描边 `#ddd6c6`；
- 状态节点填充用语义色（金/橙/黑）。

### 5.1 SVG 分发场景的字体适配（对外分发必做）

SVG 以源文件分发（README/网页）时，渲染发生在**访客机器**上：访客没装思源宋体/Noto，浏览器回退到微软雅黑等更宽字体，拉丁与标点字宽可 +10~20%，原作者机器上"刚好放下"的文字在访客侧出边界/压线。

1. **文字预算按回退字体最宽值计算**：CJK 字宽恒为 1em 不变；拉丁/数字/标点按 +15% 估；长句优先缩短或拆行，不靠精确字体度量。
2. **必跑 `assets/svg-autofit.js`**：浏览器加载 SVG → 执行脚本（注入微软雅黑模拟 → 检测画布越界/容器越界/文字互压 → 自动缩字，下限 9px）→ 把返回的 xml 写回文件 → **重跑一遍应报 fixes=0**。
3. 残余越界（缩到 9px 仍放不下）= 文案问题，必须缩短文字，禁止再压字号。
4. 内嵌进 PDF/HTML 的图不必跑（字体已随介质确定）；作者机器目检不能替代本检查——它测的是访客的字体。

## 6. 绝对定位白名单

只有 `.ring` 允许绝对定位，角度用内联 `--a`（如 6 节点：-90/-30/30/90/150/210deg），
半径 `--r` 与节点直径 `--node` 按画幅在模板里给定，**不得现场调参**。其余图一律 flex/grid。

## 7. 四类质量问题的排查与修正

| 问题 | 机器检查 | 人工排查点 | 修正手段（按序尝试） |
|---|---|---|---|
| 文字出边界 | `diagram-check` 报 `overflow-x/y` | 截图看节点底部是否顶满、末字是否被裁 | ① 缩一档字号 ② 文案砍字/换行 ③ 减列数加宽节点 ④ 拆图 |
| 文字压线 | 检查 `.lab/.elab` 是否带背景；截图目检 | 标签与线交叠处是否可读 | ① 套芯片底色 ② 标签上移/下移半行 ③ 线改道（加 row-gap） |
| 线条紊乱 | 截图数交叉与折角 | 是否出现斜线/曲线/穿框 | ① 统一方向 ② 长回边改注记行 ③ 交叉>1 重排 ④ 拆图 |
| 错位重叠 | 检查同容器兄弟节点矩形相交 | 基线是否对齐、列是否等宽 | ① 去 absolute 改 grid/flex ② 加大 `--gap` ③ 对齐轴统一（列中心/行基线） |

**QA 循环（每次配图必走）**：
构建 → 浏览器加载页面 → 执行 `diagram-check.js`（Playwright `browser_evaluate` / 控制台均可）→ 有报错先修 →
逐图截图目检（对照上表"人工排查点"）→ 再跑一遍检查 → 通过才进入排版输出。
**注意**：SVG 手搭图（§5）不走机器检查，必须逐图截图目检；`.page` 有 `overflow:hidden`，
超高内容会被静默裁切，所以"逐页看完整"是硬要求（`[clipped-*]` 报告就是抓这个）。

## 8. 公众号版配图：内嵌优先，卡片降级兜底

微信正文不支持 absolute 与可靠 flex，但**支持粘贴 base64 内嵌图**。两级策略：
1. **优先：整图 PNG base64 内嵌**——按 §1.5 配额产出的图逐张渲染截图（宽 ≤1080px、单图 ≤300KB），以 `<img src="data:image/png;base64,...">` 内嵌到对应位置，粘贴时微信自动转存素材图；
2. **兜底：卡片降级**——拿不到 PNG 渲染条件时才降级为纵向卡片：时序图→步骤列表卡（1. → 2. → 3. 纵向芯片）；架构图→每层一张横条卡纵向堆叠，层名做左侧灰字；环形图→改用芯片链。
严禁 `<img src="file://...">` 与外链图——粘贴时必被丢弃。
