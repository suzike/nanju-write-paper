# Markdown → 版式模块映射规则

> 输入是用户写好的 Markdown 文案；输出按 [style-guide.md](style-guide.md) 的模块组装。
> 本文件同时定义「深度技术文章」的标准骨架（Phase A 产出的 final.md 应符合此骨架，排版阶段直接套用）。

## 1. 元素映射表

| Markdown | 版式处理 |
|---|---|
| front-matter `title/subtitle/series` | 封面：大标题 / 橙色等宽副标 / 系列名 |
| `# H1` | 暗色封面页；若文中有明确流程，可生成环形图或芯片链 |
| `## H2`（第 N 个） | 亮色章节页：编号 `0N`（两位数，≥10 直接写 10、11）+ 标题；英文胶囊标签取标题括注（如 `## 构建 (BUILD)`），没有则省略 |
| 章节右侧制品芯片 | 取该节的"产物/结论"：代码块文件名、或小节标题中的关键对象；没有合适对象就省略 |
| H2 后第一段 | `.deck-sub` 一句话副标（若该段 >60 字，改作正文，副标从段中提炼一句） |
| 段落群（≥2 段描述同一机制/流程） | 提炼成 `.panel` 图示：步骤→流程行；分层→架构图；协作→时序图；分级→tier（见 diagram-guide 选型表） |
| `### H3` + 段落/列表 | `.points` 要点格一格：H3→小标题，内容压成 2–3 行 |
| 无小节的并列要点（列表） | `.points` 2×2 或 `.fcard` 组 |
| `> 引用` | `.callout`（橙虚线）；内容含"配置/回归/附注"语义时用 `.callout--blue` |
| ```代码块``` | `.codecard`：标题 = info string 或文件名 + " 示例"；注释行染 `.cm` |
| 表格 | 分级/阈值语义且列数 ≤3 → `.tier`；其余 → `.dtable` 紧凑数据表（米色表头）；两者都不合适再考虑 callout 转写 |
| 图片 `![]()` | 用户显式给的图才放；路径随 HTML/PDF 相对引用；公众号版需提示用户先上传素材库 |
| `---` 分隔线 | 章节分页点（亮页之间），或摘要分隔 |
| 结尾总结段/列表 | 暗色总结页 `.sumlist` + `.points` |

## 2. 篇幅与分页

- A4：每章 1–2 页；页面装不下时优先压缩要点格正文，不缩小字号
- 3:4 卡片：一章一卡；内容多拆两张（面板卡 + 要点卡），编号相同
- 长图/公众号：不分页，章节间用大间距 + 分隔

## 3. 深度技术文标准骨架（Phase A 产出目标，Phase B 直接排版）

1. **封面**：标题 / 副标 / 系列名 / 主线芯片链
2. **开篇**（为什么值得读）：问题场景 + 现状痛点 + 本文地图
3. **主体 3–6 章**，每章 = 概念定义 → 机制剖析（配图）→ 实操/代码 → 边界与坑 → 小结要点格
4. **横向对比章**（可选）：方案对比表 / 选型 tier
5. **总结页**：要点回放 + 行动建议
6. 文末：参考来源列表（Phase A 调研的 claim→source 清单）

## 4. 产物命名约定

排版输出与源 Markdown 同目录：`<name>.pdf` / `<name>.html` / `<name>.wechat.html`。
产物为**单文件**：发布前把 `assets/theme.css` 内容内联进 `<style>`（相对链接换目录会断）。
直接粘贴的文案（无源文件）放 `writing/<YYYY-MM-DD>-<slug>/`。
中间产物（Phase A）同样放 `writing/<YYYY-MM-DD>-<slug>/`（见 writing-graph.md）。
