## 2. 字体（双字体系统）

- 中文标题与正文：**衬线** `var(--serif)` = Source Han Serif SC / Noto Serif SC / Songti SC / 华文中宋 / SimSun
- 编号、标签、代码、芯片文字：**等宽** `var(--mono)` = JetBrains Mono / Cascadia Code / Consolas
- 英文胶囊标签：等宽 + `letter-spacing:.22em` + 大写
- 本机已装 Noto Serif SC（含 Black）与 Source Han Serif SC Heavy，标题用 `font-weight:900`
- **交付前字体检查**：渲染后确认标题/正文命中衬线字体（截图目检笔画是否有衬线）；回退到 SimSun 等细宋时在交付说明中告知用户"装思源宋体/Noto Serif SC 可获得参考图同款质感"

## 3. 三种页面骨架

### 封面页（暗色）
1. 左上大标题：衬线 900，3 行以内，关键词下方一条粗橙条（`.u-accent`）
2. 橙色等宽副标（系列名/英文题）
3. 中部主视觉：环形图（`.ring`，6 节点 + 中心橙块）或大面板图示
4. 底部芯片链（`.chipline`）：等宽芯片 + 橙色 `→` 箭头，表达主线流程

### 章节页（亮色，信息最重的一页）
自上而下：
1. `.sec-head`：橙色大编号 `01`（mono 700）+ 黑衬线标题 + 白胶囊英文标签（`.pill`）+ 右侧 `提交` 灰字 + 黑色制品芯片（`.chip-dark`）
2. `.deck-sub`：黑衬线 900 一句话副标（本节核心结论）
3. `.panel` 米色大圆角面板：本节主图（流程行 / 状态块 / 架构图 / 时序图 / 分级表，见 diagram-guide）
4. `.points` 2×2 要点格：橙竖条 + 粗衬线小标题 + 2–3 行正文
5. `.codecard` 通栏墨黑圆角代码卡（可省略；有代码/配置/示例时必用）

### 总结页（暗色）
1. 标题 + `SUMMARY` 暗胶囊 + 右上橙色系列名
2. 一句话总括（衬线 900）
3. `.sumlist`：编号列表（橙 mono 编号 + 粗衬线词条 + 灰褐描述 + 右侧等宽制品名）
4. `.points` 关键结论（橙竖条样式在暗页复用）
5. 底部复用封面芯片链

## 5. 画幅与字号令牌

`theme.css` 内置四档：`.page--a4`(794×1123) / `.page--card`(1080×1440) / `.page--wide`(1280×720) / `.page--scroll`(900×auto)。
字号经 `--fs-*` 变量按画幅自动缩放，**不要在模块里写死字号**，一律用变量。

## 6. 硬性规则（改动需用户确认）

1. 色板值与"橙黄黑白"语义不得漂移；蓝是点缀不是主色。
2. 中文必须衬线、编号/代码必须等宽，不得混入黑体正文。
3. 圆角、面板底色、页边距按画幅令牌，不手调像素。
4. 每个亮色章节页必须有：编号头、一句话副标、至少一个面板图示。
5. 暗页只用于封面与总结（一篇文档首尾各一），中途不插暗页。
6. 公众号 HTML 一律内联样式（见 wechat 模板），禁用 class/外部资源/absolute 定位；**同时禁用 float 与 box-shadow（微信编辑器会剥离）**，右对齐注记降级为行内「· 分隔」。
7. **版面密度红线**：内容版面占用 55–75%；页底空白 ≤15% 页高；禁止连续两张近空页；配图用满宽；代码卡用 `.codecard--dock` 停靠页底，总结列表用 `.sumlist` 弹性撑满。页面内容少时优先扩内部间距与字号令牌，而不是留白。
8. **画幅形态规则（选画幅即选形态）**：
   - **16:9 宽屏 = 演示形态**：每页必须有视觉主体（图 / 表 / 卡组 / 大数字 / 引文卡）；**纯文字页禁止**；单页正文 ≤350 字；叙述长句压缩为卡片短语，完整论述留给 A4 版。配图配额在演示形态下上浮：真图 ≥5、图式 ≥4 种。
   - **A4 / 手机长图 = 文章形态**：图文并茂，双栏正文可用，文字量不设上限（守密度红线即可）。
   - **3:4 卡片 = 半图半文**：一章一卡，图占上 half、要点占下 half。
   - 选定画幅时主动告知用户形态差异；PPT 形态下，大纲里的段落型章节必须转译为"图 + 卡"叙事，而不是删字了事。
   - HTML 交付物分两种形态（§7 第 11 条）：**卡片型**（.page 分页容器，本地浏览）与**连续文流型**（发表给他人阅读）——由"谁来读"决定，不由格式名决定。

## 7. 跨介质交付规范（十条例，来源：演示设计/平台限制/打印规范调研）

1. **公众号图表 = PNG 预渲染 + base64 内嵌**：微信白名单剥掉 style/SVG，外部 `file://` 链接的图粘贴时必死——所有图预渲染为 PNG（宽 ≤1080px、单图压缩至 ≤300KB），以 `data:image/png;base64` data URI 内嵌进 HTML（`<img src="data:..." style="max-width:100%">`）。粘贴时微信编辑器自动把 base64 图转存为素材图，**无需手动上传**；正文其余部分只写白名单内联样式。
2. **长图平台硬限**：宽 890–1080px、单张高 ≤5000px、宽×高 ≤600 万像素，超限自动切成无缝分段图；密度按"一屏一信息单元"校验。
3. **断言式标题**：演示页标题写成完整结论句（"X 翻倍/方案 Y 可行"），页面主体放视觉证据；无法视觉化则拆页。
4. **演示页密度下限**：每页要点 ≤6 条、数据表 ≤6 数据行（超限转图表/拆页）、正文字号不低于画幅令牌下限。
5. **公众号随稿产出**：2.35:1 封面图（主体居中防裁切）+ ≤120 字摘要，与正文同时交付。
6. **3:4 安全区**：关键内容置于中部，四周留 ≥100px；底部 25%、右下角、四角圆角区不放标题/主体/二维码。
7. **打印提示**：深色页打印墨耗约为文字页 20-30 倍——打印场景主动提示，可提供浅色变体；反白小字打印可读性差。
8. **A4 打印规范**：显式 `@page { size: A4; margin }` + 页码；表格/代码块/图表 `break-inside: avoid` 禁跨页断裂。
9. **Web 加固**：HTML 带 viewport meta + 画幅 letterbox（宽取 min(100vw, 16/9·vh)）+ `color-scheme` 声明，避免纯黑纯白被暗色模式强制反色。
10. **降级地图**：多画幅交付附"砍了什么、细节去向"说明（A4→PPT→卡片）；演示页被压缩的细节在交付说明中指回完整版章节。
11. **发表型 HTML 一律连续文流**：公众号/博客等"发表给他人阅读"的 HTML，禁止 `.page` 固定页容器、禁止页码、禁止"见 PXX"式页码引用——分页卡片只适合本地浏览（发群文件/截图分享），粘进滚动流会把叙事切断、页码与目录引用全部失效。章节衔接靠小标题与过渡句，图表行内随文。卡片型与连续型可同时交付（双版本），由用途决定而非二选一。
