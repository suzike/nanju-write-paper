01 缘起：两年三级跳，从个人项目到爆款底座

写 pi 的人叫 Mario Zechner，GitHub ID 是 badlogic——Java 游戏框架 libGDX 就是他的作品，社区养了十几年还活着。这种履历自带信用：他见过一个项目怎么长大，也见过它怎么死。按他自己的说法，做 pi 是因为现有的 coding agent "往上下文窗口里塞了太多东西，还把正在发生的事藏起来"（大意，出自 2025-11-30 的设计博文）。

引爆点在 OpenClaw（2026 年初走红，旁证称病毒式传播，未量化核实）——它的底层 agent 框架就是 pi。做底盘的项目，因为别人在它上面造出了爆款整车，被更多人看见。第一眼看到 98.8k 的星数（单源抓取，2026-08-29）我以为是写错了，后来想明白，它早就不是"个人项目"三个字能概括的东西。

02 架构解剖：一轮对话是一圈循环，没有步数上限

你在终端敲下"帮我修复这个报错"，消息进入 pi-ai——名字像模型适配库，实际上把 agent loop 也做进去了：发给模型、流式回收、把工具调用的参数碎片聚合成完整对象、执行工具、结果回填、再问一次，循环到模型停手。跨 provider 接力也在这层：上半场用 Claude 读代码库，下半场切 DeepSeek 继续干，上下文跟着走。

整个项目是 TypeScript 单仓，拆成五个能独立安装的包：pi-ai（统一模型 API + loop）、pi-agent-core（事件运行时，口号 "Everything is an event"）、pi-tui（自研差分渲染终端 UI）、pi-coding-agent（CLI 组装）、pi-telemetry（遥测契约）。上下文纪律也很硬：全项目只有 AGENTS.md 会被注入提示词，甚至可以用 .pi/SYSTEM.md 把系统提示词整个换掉。

03 四工具哲学：模糊匹配是 edit 的机关

模型自己的判断力是第一道防线——系统提示词全文不到 1000 tokens。

read 分页 + 行号，按 offset 翻页，能读图片

write 整文件覆盖，没有花活

edit diff 格式 + 模糊匹配：容忍模型输出的空格缩进漂移，成功率就上来了

bash 执行命令 + 超时；长驻进程交给 tmux

SYSTEM PROMPT · 模型自己的判断力是第一道防线

安全思路一脉相承：没有内置权限系统，按启动用户权限直接跑，官方建议放容器（Docker / Gondolin / OpenShell）；轻量玩法是只读模式 pi --tools read,grep,find,ls，只带眼睛不带手；供应链纪律也细——安装命令自带 --ignore-scripts，还有依赖锁版、最小存活期、脚本白名单。风险没有消失，只是从工具侧挪到环境侧，变成你的显式选择。

03 六个"No"是立场，不是缺口

No MCP · 用带 README 的 CLI 工具（见 Skills），或写扩展加上 MCP 支持

No sub-agents · tmux 起 pi 实例，或写扩展，或装别人做好的包

No permission popups · 放容器里跑，或写自己的确认流程

No plan mode · 计划写成文件，或写扩展，或装包

No built-in to-dos · "它们会把模型搞糊涂"，用 TODO.md 或扩展

No background bash · 用 tmux，全量可观测

第一遍读以为是偷懒的体面说法，第二遍才反应过来：每个 No 后面那句"你可以自己造"才是正主。这六个 No 是立场，不是缺口。

04 上手：十分钟跑起来，坑在 Node 版本

quick start

# 安装（Node ≥ 22.19.0，v0.84.4）

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

# 登录二选一

export ANTHROPIC_API_KEY=sk-ant-... 然后 pi；或 /login 走订阅

订阅认 Claude Pro/Max、ChatGPT Codex、GitHub Copilot 三家；API key 约 30 家 provider，本地模型走 llama.cpp / Ollama。最有辨识度的是会话系统：会话是 JSONL 树，Esc 按两次进树视图，跳回任意历史节点接着聊；/fork 是"回到过去改个决定"，/clone 是"平行世界再来一遍"。打字时 Enter 排的是纠偏消息（steering），Alt+Enter 排的是完工后消息（follow-up）。从 Claude Code 迁移几乎无痛：CLAUDE.md 它也认，/compact 它也有，24 个命令 /hotkeys 查全。

05 扩展系统：极简的反面是可编程

扩展就是一个默认导出的工厂函数，API 三件事：registerTool 注册工具、registerCommand 注册命令、on("tool_call") 拦截每一次工具调用。官方仓库躺着 50 多个示例——六个"No"每个都有参考实现：subagent/、plan-mode/、permission-gate、sandbox/，甚至有等结果时打 Doom 的扩展。skills 遵循 agentskills.io 标准，/skill:name 调用。

protected-paths.ts · 官方示例（节选）

export default function (pi: ExtensionAPI) {

  const protectedPaths = [".env", ".git/", "node_modules/"];

  pi.on("tool_call", async (event, ctx) => {

    // 命中保护路径 → return { block: true, reason }

  });

}

这段代码我从头读到尾花了半分钟。这才是重点：你真的可以读完你的 agent 的全部行为。社区也已有成型第三方包（oh-my-pi 把 LSP、浏览器、子代理打包进来；pi-mom 接 Slack），作者本人更绝，把自己的开发会话全部公开在 Hugging Face 上——这个项目是被它自己造出来的。

06 横向定位：底盘 vs 整车

维度  |  pi  |  Claude Code  |  OpenCode

许可 · MIT 全开源 | 闭源订阅制（通识，存疑） | 开源

MCP · 刻意不做 | 有 | 有

sub-agent · 无内置有示例 | 有 | 有

扩展 · TS 扩展+pi package | MCP+hooks+skills | MCP+plugins+SDK

模型 · 16+ 供应商+本地 | Anthropic 为主 | 多供应商

计费 · 免费无定价页 | 订阅制 | 未标注

底盘：pi——每一处都能改，扩展、skills、主题全是你的代码；代价是组装和维护归你。

整车：Claude Code / OpenCode——上路就能开，MCP、sub-agent、权限全是产品功能；代价是路线归别人画。

模型自由度上还有个差异：pi 的 /model 会话内热切换，配合跨 provider 上下文接力，一条工作流混用两家模型是常规操作。

07 批判：极简的账单，六笔都有出处

第一笔，无 MCP。连头号拥趸都列为第一缺点。这里必须交代立场：那篇好评整体是软文，作者自称 shill，且与 Zechner 同在 Earendil。自己人说"缺失最明显"，分量反而更重。

第二笔，无现成生态。"no community skills, nothing"；Reddit 实测也说没有 find、git、sub-agent（转引，原帖未读全）。能力获取基本等于自己写代码。

第三、四笔，TS 门槛与自建维护。深度定制的入场券是会写 TypeScript；自建扩展是自己的代码，模型升级行为漂移得自己修（这两句是我的推断，非用户引语）。

第五笔，商业化悬念。加入 Earendil 消息出来后，社区立帖"enshitification?"；Zechner 在官宣博文里承诺 MIT 不变，未来商业功能走 Fair Source。截至发稿没有背刺实锤，但包名迁移的成本已经真实发生。

第六笔，好评的圈层。最重要的几篇好评，作者要么在 Earendil 要么和它互相依存；HN 上流传最广的那句"linear flow 沮丧"我查了原文，是 Zechner 在骂别家。这个圈子的好评要打折听。

三段原声 · 立场已标注

"The most obvious omission is support for MCP." —— Ronacher（利益相关已披露）

"pi is MIT licensed. It will stay MIT licensed. Nothing changes." —— Zechner，官宣博文

"Or not, I don't know :)" —— Ronacher 谈 MCP 桥接可靠性：拥趸的态度是"我不知道"

收个清单，五种情况别用 pi：团队依赖现成 MCP 生态；要开箱即用的全家桶；不会 TS 又想深度定制；IDE/GUI 重度用户；对许可分层过敏的组织。反过来，想完全掌控 harness、愿意读源码的高级开发者，它可以闭眼试。还有件没查明白的事：Earendil 靠什么把 pi 变成生意——pi.dev 上没有定价页，这是我能确认的全部。
